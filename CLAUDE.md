# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Two independent single-file Node.js tools for Claude Code **plus a companion mod plugin** (`mod/`, v3.5.2), no dependencies beyond Node's built-in modules (`fs`, `path`, `os`, `readline`, `child_process`, `url`, `https`) and no build step, package manager, or test suite — everything is meant to be run directly with `node` (the mod is plain ESM, no build).

- **`statusline.js`**: implements both a main status line and a subagent status line.
- **`pricing-updater.js`**: fetches live model pricing from the community-maintained litellm price table and writes/merges `~/.claude/pricing.json` (or a chosen `--out` path — the maintainer uses `--out pricing.json --overwrite` to refresh the repo's shipped copy), which `statusline.js` reads to self-compute session cost. Only this tool touches the network; the status line itself never does.
- **`mod/`** (v3.5.0): the companion mod — a Claude Code plugin (`cc-statusline-mod`) that runs in-process. It records per-request usage straight from `turn.step` events (no transcript parsing), draws a single toggle button in the `AbovePrompt` band (default `✳` in Anthropic terracotta `#D97757` — Claude Code's own TUI family; restyle glyph/hotkey/color via `toggle`) that opens a **one-view launcher**: every function on screen at once, nothing behind a tab (3.4.0's tabs were dropped — real-machine feedback wanted one-click-to-everything with minimal nesting). Sections are **cards**: rounded borders in the section color (`⚡快捷切换` yellow / `✏提示词` cyan / `🔗链接` blue / `$命令` green / `◆group` gray custom) with the bold colored header inside; 快捷 and 提示词 lay out **two aligned columns** (fixed-width-20 cells on a `flexWrap` row — wraps below ~44 cols instead of clipping), links and commands one per line with their target shown dim beside the label (bookmark address / the actual argv, e.g. `git状态  git status -sb`), the finished command's result line colored green/red by exit code. Button labels carry NO emoji — terminals render emoji at inconsistent widths and they collide with the label text (real-machine-verified); emoji live only in section headers. The template ships **real engineering content**: quick switches (`/fast`, `/permissions` — **the mods API has no permission-mode setter**, verified 2026-10-26, so permissions opens CC's dialog; `/model`, `/compact`, the usage pane) and 10 curated daily prompts (继续任务/测试并修复/审查改动/修复告警/重构文件/补文档/写提交/定位bug/性能分析/解释架构), plus universal git commands (`status -sb`, `pull --ff-only`) and repo-labeled npm examples — 22 buttons, hotkeys globally unique. The toggle must issue `open`/`close` **synchronously inside the press dispatch** — an open after an `await` counts as plugin-initiated and the pane waits undrawn below 144 columns (`{ isPlaced: false, reason }` is toasted, not swallowed); then the same one view expands **inline in the band**, so the launcher works at any width. Toggle direction tracks `$.ui.panes()` (refreshed each band draw) plus module state; slash/prompt buttons collapse whichever launcher form is up first (via `collapseLauncher($)` — called at the press site so `$` stays in the handler's scope), every path toasts. `/ccsl-usage` + usage pane (sparkline + totals) unchanged. Custom buttons live in `~/.claude/ccsl-buttons.json` (auto-created with the template; `/ccsl-buttons` reloads); **a file that byte-matches a past factory template auto-upgrades to the current one** (`LEGACY_TEMPLATES` — the never-overwrite rule bit twice in the wild: an untouched 3.1.0 demo file kept hiding new features, so untouched files now refresh in place while hand-edited ones are always preserved; append the outgoing template there whenever `configTemplate()` changes). Labels/groups are clipped by code point (`Array.from`) so an emoji never splits into U+FFFD. Every mods-API call in `mod/hooks/register.mjs` is wrapped in `safe()`; `$` nouns are only ever called inside the hook that bound them. `--install` copies `mod/` to `~/.claude/skills/cc-statusline-mod/`; one-session preview: `claude --plugin-dir mod`.

The v1.x `loopctl.js` (Stop-hook auto-continue loop) was removed in 2.0.0 — Claude Code has native `/goal`. `scripts/postinstall.js` still cleans up its leftovers (Stop hook registration, `~/.claude/loopctl.js`) on upgrade.

## Commands

There is no build/lint/test tooling in this repo. Useful commands:

- Run the status line manually against sample main-session input: `echo '{}' | node statusline.js`
- Run it against mock subagent-row input (must include a `tasks` array to trigger that code path): `echo '{"tasks":[{"id":"t1","name":"Explore","tokenCount":100,"startTime":"2026-01-01T00:00:00Z"}]}' | node statusline.js`
- Install/update the status line as both the active `statusLine` and `subagentStatusLine`: `node statusline.js --install` (copies itself to `~/.claude/statusline.js` and updates both fields in `~/.claude/settings.json`, prompting independently before overwriting either existing file/setting; when writing the `statusLine` object it also adds `hideVimModeIndicator: true` and `refreshInterval: 5` if absent — the script renders vim mode itself so CC's `-- INSERT --` would double it, and a periodic tick keeps renders fresh while the session idles on subagents; user-set values are never overwritten) — same thing via `install.bat` on Windows, `install.sh` on macOS/Linux, or `npm run install`
- Refresh pricing: `npm run update-pricing` (merge into `~/.claude/pricing.json`) or `node pricing-updater.js --out pricing.json --overwrite` (maintainer: refresh the repo's shipped copy). A bare `pricing-updater` run IS the default merge — this was fixed in 2.0.0 (it used to print help, contradicting the docs and the npm script).
- Simulate renders: `npm run demo` (empty payload) / `npm run demo:subagent` (mock subagent rows)
- Try the companion mod for one session without installing it: `claude --plugin-dir mod` (band buttons, `/ccsl-usage` pane)
- Quick syntax check: `npm run check` (runs `node --check` on all scripts, then `scripts/check-version.js` — verifies statusline.js's embedded `VERSION` matches package.json; the const is embedded because the `--install` copy at `~/.claude/statusline.js` has no package.json beside it)

## Architecture

The script runs in two distinct top-level modes based on `process.argv`:

1. **Install mode** (`--install` flag): `installStatusLine()` copies the running script to `~/.claude/statusline.js` and wires up `~/.claude/settings.json` so Claude Code invokes it as both `statusLine` and `subagentStatusLine` (same file, same command — the script tells the two inputs apart at runtime, see below). It diffs file content / existing settings before touching anything and prompts the user via `promptYesNo()` independently for the script copy, the `statusLine` setting, and the `subagentStatusLine` setting.

2. **Render mode** (default, no args): Claude Code invokes the script as a subprocess and pipes a JSON payload on stdin. The script reads all of stdin, parses it once `process.stdin` emits `'end'`, and writes to stdout. Within render mode there are two payload shapes, distinguished by whether `data.tasks` is an array:
   - **Subagent rows** (`subagentStatusLine`): payload is `{ columns, tasks: [...] }`, one entry per visible subagent row (`id`, `name`, `type`, `status`, `agentType` — v2.1.293+, renders a dim `[type]` badge when it differs from the row name — `tokenCount`, `startTime`, `tokenSamples`, `contextWindowSize`, `effort`, ...). Handled by `renderSubagentStatusLine()`, which must emit one NDJSON line per task as `{"id": "<task id>", "content": "<row>"}` — omitting a task's `id` keeps Claude Code's default row rendering, and an empty `content` hides it.
   - **Main session** (`statusLine`): payload has session info, `cwd`, `transcript_path`, `cost`, `context_window`, `rate_limits`, `prompt_cache`, etc. This is the original/default path.

Key implementation detail: **output-token/timing data for the main status line is not present in the stdin JSON.** Claude Code's stdin payload only has coarse session cost/duration. To compute output tokens-per-second (TPS), the script re-parses the JSONL transcript file at `data.transcript_path` line-by-line, pairing each `assistant` message's `usage.output_tokens` with the timestamp of the preceding `user` message (prompt or tool_result) to derive elapsed generation time. Subagent (`isSidechain: true`) entries live in the same transcript file but describe a different conversation: they are excluded from the main line's TPS / out / cache figures (subagent rows render their own rates) — but they ARE included in the session-wide Σ input/output totals, which represent the whole session's spend. The Σ accumulation counts every assistant turn (excluding cache-read tokens from the input sum, since those repeat every turn and would inflate the total).

For subagent rows, real stats come from the agent's own transcript when it exists: Claude Code writes background/local agents to `<project dir>/<session id>/subagents/agent-<task id>.jsonl` (the subdir is named after the session id, sitting next to the session transcript in the project dir) with the same assistant/user entry shape as the main transcript, so `agentTranscriptStats()` applies the same TPS pairing and total accumulation (context % from the last usage, cumulative out/in/cache split, cost via the pricing table keyed by `task.model`). This fallback exists because the payload's own `tokenCount`/`tokenSamples` stay 0 for whole runs on current builds (verified by payload capture; `tokenSamples` is a plain array of numbers there, which `estimateRecentRate()` deliberately can't rate — no timestamps). Without a transcript, the row falls back to `tokenSamples` (labeled `tok/s` — coarser than transcript-derived `TPS`) or `tokenCount / (now - startTime)`. Zero/absent `tokenCount` and zero/absurd rates are omitted rather than rendered as `tok:0(0%)` / `0.0tok/s` — a displayed zero reads as a frozen row. The row also shows the live activity label (`task.label`, falling back to `description`, truncated to ~48 chars), which updates every refresh tick and is the strongest liveness signal on zero-token builds. Because the payload shape is undocumented, the script has an opt-in capture facility: when `~/.claude/statusline-debug` exists, every render appends its raw stdin payload to `~/.claude/statusline-payloads.log` (best-effort, size-capped ~512KB by dropping oldest lines, never breaks rendering) — the sanctioned way to learn what Claude Code really sends before touching the parsing. The main line's TPS carries an age marker (`TPS:N (Xm ago)`) once the underlying message is over 2 minutes old, since the figure is stale by design while the main conversation waits on subagents.

Rendered segments on the main line (all conditional — absent data renders nothing, never zeros):

- **Line 1** (identity/workspace): model, OSC-8 clickable `file://` link to the cwd, git branch (itself an OSC-8 link to the branch's browse page when `buildBranchUrl()` resolves one), PR/MR number + review state (GitLab merge requests render `MR#` via `pr.kind`; OSC-8 link to `pr.url` when present), session name, worktree name (`🌳wt:` from `data.worktree` for v2.1.x worktree sessions, falling back to `workspace.git_worktree` for plain linked-git-worktree checkouts), agent name (`🤖` from `data.agent`), context-window usage % colored by `colorForPercentage()` with the total window size appended (`ctx:23%/1M` from `context_window.context_window_size` — meaningful again now that 1M-context sessions are common).
- **Line 2** (activity/cost/mode): TPS (with age marker), output tokens, last-response cache tokens, prompt-cache health (`pc:87%(5m)` — `hit_ratio` × 100 with a `(cold)` label when `!warm`, green ≥80 / yellow ≥50 / red below; `hit_ratio` arrives as a 0..1 fraction on current builds, guarded against a 0..100 scale), plus a yellow `⚠<cause>` diagnostic from `prompt_cache.last_miss_cause.causes` when Claude Code identified one (v2.1.260+; `tools_changed`/`system_prompt_changed`/`ttl_expired_5m`/`likely_server_side` render as `tools`/`sysprompt`/`ttl5m`/`server`), session totals Σ↓/↑, lines added/removed, self-computed cost (or `~cost?:` client-estimate fallback), duration, 5h/7d rate-limit % each with a compact time-to-reset from `resets_at` (`formatUntil()`, suppressed when absent/in-past/>48h), spend-limit (`sp:` — `$used/$limit` with period suffix `d`/`w`/`mo` from `used_usd`/`limit_usd`/`period` when the gateway sends dollars, v2.1.284+, optional fields that can lag `used_percentage` by ~5min; else `sp:%`; can exceed 100), fast mode, extended thinking, reasoning effort, vim mode, non-default output style (`style:`), the Claude Code version (`v2.1.258`) for debugging, and the script's own embedded version (`ccsl2.x`, the `VERSION` const) last — npm never refreshes the `~/.claude/statusline.js` copy on its own, so the marker makes stale installed copies visible at a glance.

Other notable behaviors:
- `findGitDir()` / `getGitBranch()` resolve the current git branch by reading `.git/HEAD` directly (handling both real `.git` dirs and `gitdir:` pointer files used by worktrees/submodules) for speed, falling back to spawning `git branch --show-current` only if that fails.
- `buildBranchUrl()` turns `workspace.repo.{host,owner,name}` (already parsed by Claude Code from the `origin` remote — no extra `git remote` call needed) plus the resolved branch name into a clickable "browse this branch" URL. Each host has its own path shape (GitHub/GitLab use `/tree/`-ish paths, Bitbucket uses `/src/`); unrecognized hosts (self-hosted Git, etc.) return `null` and the branch renders as plain text rather than a guessed-wrong link. A detached-HEAD short hash (from `getGitBranch`'s fallback) also returns `null` since it isn't a branch page. When a URL is available, the branch segment is wrapped via `osc8()` (the generic OSC-8 helper; `osc8FileLink()` is the cwd-specific wrapper around it).
- Width-aware rendering: Claude Code sets `COLUMNS` before each render (output is captured, so `tput` can't work); `fitLine()` drops least-essential segments first (drop order in `LINE1_DROP`/`LINE2_DROP` — model/dir on line 1 and TPS/cost on line 2 are never dropped) instead of wrapping mid-segment, and subagent rows shrink their activity label to the payload's `columns` (`stripAnsi()` measures visible width — OSC-8/CSI sequences cost no columns; label dropped entirely below a 4-col budget). Manual runs without `COLUMNS` keep everything. The `PR#`/`MR#` segment is an OSC-8 link to `pr.url` when present, and the `🌳wt:` segment links to `worktree.path` in worktree sessions.
- `cost.total_cost_usd` is a client-side estimate documented as potentially diverging from the actual bill, and it is priced at Anthropic's rates even when you route to a third-party model (e.g. MiniMax or GLM via `ANTHROPIC_BASE_URL`), so the script does **not** display it verbatim. Instead it self-computes cost from the transcript token counts (split into fresh input / output / cache-read / cache-creation, accumulated session-wide in the parse loop) times a public, editable pricing table that lives in **`pricing.json` next to the script** — one file, the single source of truth. `loadPricing()` reads `path.join(__dirname, 'pricing.json')` best-effort (missing/invalid → `{}`, in which case cost falls back to the client estimate); `resolvePricing(model, table)` matches by exact name then longest case-insensitive substring (so `glm-5.3[1m]` matches `glm-5.3`); `computeCost()` is the rate×tokens formula. The self-computed figure is shown as `~cost:`; when the current model has no pricing entry (and only then) it falls back to `total_cost_usd` shown as `~cost?:` to flag that it's the untrusted client estimate. Both are estimates — hence the `~` prefix — don't "fix" this by dropping the prefix. `--install` seeds `~/.claude/pricing.json` from the repo's bundled `pricing.json` **only if the target doesn't exist** (never overwrites — the user may have refreshed it), so cost works out of the box. `pricing.json` is maintained by `pricing-updater.js`, which fetches live rates from the litellm price table (sourced from each provider's official pricing page — no official JSON API exists) and merges them into `~/.claude/pricing.json` on demand — **manual run only, no scheduled task**, by design (silently rewriting rate data in the background is risky). The maintainer refreshes the repo's shipped copy with `--out pricing.json --overwrite` and commits; users refresh their own with a bare `pricing-updater` run. A manual run also best-effort checks the npm dist-tags for a newer release and prints an upgrade hint (read-only GET, 3s timeout, silent offline) — the closest thing to auto-update this package gets, since npm never refreshes global installs, nor the `~/.claude/statusline.js` copy, by itself. `pricing-updater.js`'s `defaultKeys()` extracts the canonical chat model of every mainstream provider (Anthropic, OpenAI, Google/Gemini, MiniMax, DeepSeek, Meta/Llama, Mistral, xAI/Grok, Cohere, Qwen/Dashscope, Z.ai/GLM, Moonshot/Kimi) with all versions: it filters `mode === 'chat'`, keeps only `MAINSTREAM_PROVIDERS` entries, and `isCanonicalKey()` rejects hoster/regional duplicates (bedrock/vertex/openrouter/azure/…, 2+ slashes) and `ft:` fine-tunes. Each model dedupes to one friendly key (substring after the last `/`), preferring bare no-slash keys so a collision like `deepseek-chat` (bare) vs `deepseek/deepseek-chat` resolves to the bare one. Don't relax the canonical filter without re-reading why — without it every model explodes into dozens of regional duplicates that collide on the friendly key.
- At the very end, there's a best-effort, opt-in integration that broadcasts session activity to an "AutoClaude" sensor. It is gated on the `AUTOCLAUDE_BROADCAST` env var, which must point at a `broadcast.js` module exporting `buildFrame`/`sendFrame`. When unset (or the path is missing), the block is a no-op. This is wrapped in try/catch and must never block or break the status line — treat it as optional/environment-specific, not a project dependency to package or generalize. This only runs in the main-session path, not the subagent-row path.

### Auto-publish to npm

`.github/workflows/publish.yml` runs on every push to `main`. It compares the version in `package.json` to the latest published version on npm; only when they differ does it: (1) publish to `@tangjianfang/claudecode-statusline`, (2) publish to `@tangjianfang/cc-statusline` (after swapping `name` in the ephemeral checkout), (3) push the matching `vX.Y.Z` git tag, (4) create the GitHub Release via `softprops/action-gh-release` with auto-generated notes. `--ignore-scripts` is used so the publish step doesn't recursively trigger the repo's own `postinstall`. CI auth uses the `NPM_TOKEN` secret (granular token, publish scope on both packages) — note npm is deprecating 2FA-bypass tokens (direct publish stops working around Jan 2027, per the [npm security changelog](https://github.blog/changelog/2026-07-08-npm-install-time-security-and-gat-bypass2fa-deprecation/)); migrate the workflow to npm trusted publishing (OIDC, tokenless) before then. The release flow is documented in README under "Releasing a new version (maintainer)".

### scripts/postinstall.js

Wires the status line on `npm install -g`: runs `statusline.js --install --yes` (auto-confirming prompts — `--yes` is only ever passed from this script), then best-effort cleans up v1.x loopctl leftovers: filters any `hooks.Stop` entries whose command references `loopctl.js` (other Stop hooks are untouched) and deletes `~/.claude/loopctl.js` + `~/.claude/loop-state.json`. All failures are logged and non-fatal (exit 0) so the npm install still succeeds.

### Package-manager compatibility (npm / Bun / pnpm / Yarn)

The package installs and runs under every mainstream package manager (README has the verified matrix). Modern managers block package install scripts by default, so the wiring postinstall needs a one-line approval: npm 12+ uses `--allow-scripts=@tangjianfang/claudecode-statusline` (or a persistent `npm config set allow-scripts=… --location=user`), Bun uses `bun pm -g trust <pkg>`, pnpm v10+ uses `pnpm approve-builds -g`. npm ≤ 11 and Yarn Classic run it automatically. Yarn Berry removed `global add` entirely, so Berry users add it as a project dependency and run `cc-statusline --install` once. Two facts are baked into the code — don't undo them:

1. **Never register Bun's temp `node` shim as an interpreter.** When Bun runs lifecycle scripts it spawns a `node` compatibility shim in the OS temp dir (`…\Temp\bun-node-<hash>\node.exe`), and `process.execPath` inside those scripts points at that throwaway copy. `statusline.js`'s `resolveInterpreter()` detects Bun via `process.versions.bun` (the `Bun` global does NOT exist in shim mode, so `Bun.execPath` is only usable when run directly by bun) and resolves the real binary: `Bun.execPath` → `$BUN_INSTALL/bin/bun(.exe)` → PATH scan (skipping any `bun-node-` shim dir) → bare `bun`. Registering the shim would silently kill the status line the next time the OS cleans the temp dir.
2. **Never re-introduce a dependency on `@tangjianfang/cc-statusline`** (the v1 alias package, removed in 2.0.0). Bun installs dependencies of global packages, which would pull the old v1.0.1 package with its v1 install scripts (including `loopctl.js --install`); `bun pm trust --all` would then run those and re-register the removed loopctl.

The render path itself needed zero changes — everything used (fs/path/os/readline/child_process/url/https, stdin `'data'`/`'end'` streaming, ANSI/OSC-8 output) is implemented by Bun's Node compat layer, verified end-to-end (main line incl. transcript TPS + self-computed cost, subagent rows, debug capture).
